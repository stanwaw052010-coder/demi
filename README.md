# Dental Clinic Nataly — сайт стоматології у Тернополі

Односторінковий сайт клініки Наталії Жилан: Next.js 16 (App Router) · React 19 ·
TypeScript · TailwindCSS 4 · Framer Motion · Lucide.

## Запуск

```bash
npm install
npm run dev     # http://localhost:3000
npm run build   # продакшн-збірка
npm start       # запуск продакшн-сервера
```

## Структура

```
src/
  app/
    layout.tsx        шрифти, метадані, JSON-LD (schema.org/Dentist)
    page.tsx          композиція секцій
    globals.css       дизайн-токени, утиліти (container-x, glass, eyebrow…)
    icon.png          favicon
  components/
    site/             header, topbar, footer, logo, мобільна CTA-панель
    sections/         hero, stats, services, prices, why-us, before-after,
                      process, doctor, kids, implants, space, testimonials,
                      faq, booking, contacts, map-panel
    ui/               button, accordion, counter, reveal, auto-video,
                      logo-watermark, scroll-progress, section-heading, icons
  lib/
    site.ts           контакти, адреса, графік, навігація
    content.ts        послуги, прайс, переваги, кейси до/після, відгуки, FAQ
    utils.ts          cn()
public/                 logo-dark/light.png, logo-mark-*.png — фірмовий знак
public/og.jpg           картка для месенджерів і соцмереж (1200 × 630)
```

Увесь текст і контакти зібрані у `src/lib/site.ts` та `src/lib/content.ts` —
щоб змінити телефон, послугу чи відгук, редагувати треба лише ці два файли.

Усі шість карток послуг мають медіа: чотири фото, одне відео (імплантація)
і один кадр реставрації. Картка стає темною автоматично — щойно у послуги
з'являється `image` або `video` у `content.ts`.

Кейс протезування на імплантах (`implantCase` у `content.ts`) — це чотири
кадри з різними пропорціями, тому кожен має власне поле `ratio`, а дві
колонки заповнюються вручну, щоб їхні висоти збігалися. Плитки галереї
приймають необов'язкове `position` (`object-position`), коли центральний
кроп зрізає головне — саме так у кадрі лишається гравійований логотип.

Кейси «до / після» живуть у `cases` (`src/lib/content.ts`). Кожен має власне
`ratio`, тож широкі кадри усмішки й макрозйомка можуть жити поруч, і
необов'язкове `short` — коротка назва для перемикача.

Обидва кадри стоять **поруч**, підписані «До» і «Після». Спершу тут був
повзунок-порівняння, але він покладався на те, що відвідувач здогадається
потягнути роздільник — клініка повідомила, що здогадуються не всі.

`result` додає під кейсом побутове фото готової роботи (протезування).

Перемикач кейсів — плитки з мініатюрами, а не рядок слів: інакше смуга
читається як підпис, і решта кейсів лишаються непоміченими. Першим стоїть
протезування — найсильніший кейс видно одразу, без жодного кліку.

## Відео

Два ролики, обидва без звуку, у двох форматах:

| Файл                  | Розмір  | Де                                   |
| --------------------- | ------- | ------------------------------------ |
| `clinic.mp4/.webm`    | ~1,7 МБ | секція «Клініка» — обхід приміщення   |
| `implant.mp4/.webm`   | ~0,8 МБ | картка «Хірургічна стоматологія» — операція |
| `prosthetics.mp4/.webm`| ~0,3 МБ| картка «Усі види протезування» — готові коронки |

Обидва грає спільний компонент `ui/auto-video.tsx`: файл починає
завантажуватись лише після події `load` і коли секція підходить до екрана —
тож відео ніколи не змагається за канал із першим екраном. При
`prefers-reduced-motion` або режимі економії трафіку лишається постер.
У картці послуги кнопки відтворення немає навмисне: `<button>` не можна
вкладати в `<a>`, а сама картка — посилання.

Щоб замінити ролик, перекодуйте вихідний файл у обидва формати:

```bash
ffmpeg -i input.mp4 -an -vf "scale=640:-2,fps=25" -c:v libx264 -crf 31 \
  -pix_fmt yuv420p -movflags +faststart public/video/clinic.mp4
ffmpeg -i input.mp4 -an -vf "scale=640:-2,fps=25" -c:v libvpx-vp9 -crf 44 \
  -b:v 0 -row-mt 1 public/video/clinic.webm
ffmpeg -i input.mp4 -ss 1.5 -frames:v 1 public/images/clinic-video-poster.jpg
```

## Форма запису

Секція «Записатися» (`sections/booking.tsx`) працює без бекенду: дані
копіюються у буфер і відкривається Viber. Щоб отримувати заявки на пошту або
в Telegram, достатньо додати змінну оточення:

```bash
NEXT_PUBLIC_FORM_ENDPOINT=https://formspree.io/f/xxxxxxx
```

Форма надішле POST з полями `name`, `phone`, `service`, `note`.

## Прайс

Ціни надані клінікою. Секція 03 будується з `priceHighlights` (три великі
картки згори) і `priceGroups` — сім груп: консультації та гігієна, терапія,
ортопедія, дитяча, естетика, хірургія, ортодонтія. Групи стоять парами
однакової довжини, щоб у рядку не лишалося порожнеч.

| Поле       | Що робить                                          |
| ---------- | -------------------------------------------------- |
| `price`    | сума; `null` → «уточнюйте»                          |
| `to`       | верхня межа: «1 700 — 2 200»                        |
| `from`     | `true` → перед сумою стане «від»                    |
| `currency` | `"EUR"` → € замість ₴ (коронки)                     |
| `note`     | дрібний підпис під назвою                           |
| `featured` | рядок стає чорною плашкою                           |

Позиції без узгодженої суми лишаються з `price: null` — рядок показує
«уточнюйте», і вигадане число на сайт не потрапляє.

## Перший екран

`sections/hero.tsx` — темний повноекранний блок: заголовок постерним
кеглем (46 px на телефоні, до 112 px на широкому екрані), короткий опис,
біла кнопка «Запис на консультацію», дрібні контакти й фото лікаря.

Фото веде себе по-різному за шириною екрана, і це навмисно. Знімок
вертикальний (4:5). Вузький екран близький до цих пропорцій, тож там кадр
іде на всю ширину. Широкий — ні: розтягнутий від краю до краю він стає
панорамою 3:1 і зрізає портрет до лоба. Тому від `lg` фото зберігає свої
пропорції та стоїть по центру (460 px, від `xl` — 520 px).

Заголовок називає **тип клініки**, а не бренд: «Сучасна стоматологія у
Тернополі». Назва Dental Clinic Nataly уже стоїть у шапці, у футері та в
заголовку вкладки, тож набирати її ще й постером читалося як повтор.

Ієрархія тут навмисна: **заголовок великий, контакти дрібні**. Номер уже
набраний великим у чорній смузі над шапкою й у кнопці шапки.

Ще дві речі:

- заголовок **не анімується**. Це найбільший елемент екрана, тож поява з
  прозорості відкладала б показ і метрику LCP (перевірено: 4,2 → 3,3 с);
- секція не має жодного клієнтського хука — це статична розмітка, тож на
  першому екрані не виконується зайвий JavaScript.

## Графік роботи

`site.hours` перелічує **кожен день окремо** — понеділок, вівторок і далі до
неділі. Пацієнт, який перевіряє «чи працюють у четвер», не має розшифровувати
діапазон. Так графік показано у секції контактів і у футері; `site.hoursShort`
— той самий графік одним рядком для тісних місць (перший екран, чорна смуга).

## Дизайн-система

- Палітра строго монохромна: `#FFFFFF`, `#F7F7F7` (cream — світла смуга),
  `#F5F5F5` (mist), `#C2C6CA` (sand — декоративні лінії та іконки),
  `#4B5158` (clay — акцентні слова), `#2F343B` (graphite), `#111111` (ink).
- Типографіка: Manrope (variable) для всього тексту + Cormorant Garamond
  italic для акцентних слів і порядкових номерів.
- Дрібні деталі: зернистість (`grain`), прогрес-бар читання, пунктирні
  лінії, кутові засічки навколо фото лікаря.
- Радіуси 20–24px, дуже м'які тіні, скляний ефект лише в плаваючих елементах.
- Анімації: fade-up при скролі, парралакс у hero, лічильники, hover-стани.
  Усе поважає `prefers-reduced-motion`.
- Framer Motion відповідає за accordion у FAQ та зміну кейсів «до / після»;
  обидва компоненти підвантажуються динамічно. Все, що видно одразу (hero,
  хедер, scroll reveal), анімується на CSS — сторінка малюється ще до
  гідратації.

## Деплой (Netlify)

`netlify.toml` у корені задає команду збірки, теку публікації, Node 22 та
офіційний плагін `@netlify/plugin-nextjs`.

### Збірка падає на файлі з чужої теки

Симптом: `Type error` у файлі за шляхом на кшталт
`./demi-claude-dental-clinic-nataly-site-5l1idu/src/app/layout.tsx`, тобто у
вкладеній теці, якої в цій гілці немає.

Причина була у `tsconfig.json`: `include` стояв як `**/*.ts` / `**/*.tsx`,
тож TypeScript перевіряв **усе дерево репозиторію**, а не лише цей проєкт.
Якщо поруч лежить друга, застаріла копія (наприклад, розпакований ZIP
гілки), tsc перевіряє і її — а `@/*` при цьому веде в кореневий `src`, тому
помилка виглядає так, ніби зламаний саме той файл.

Тепер `include` обмежений `src` і кореневим `next.config.ts`, тож сусідні
копії на збірку не впливають. Відтворено локально: з чужою текою поруч
стара конфігурація падала точно тим самим повідомленням, нова — збирається.

Важливо: це лікує саме падіння. Який код опиниться на сайті, все одно
визначає вміст `src` у корені того репозиторію, який збирає Netlify.

### Netlify збирає не цю гілку

Симптом: збірка падає на помилці типів, якої локально немає, а шлях у логу
містить теку на кшталт `demi-claude-dental-clinic-nataly-site-5l1idu/src/…`.

Такої теки в репозиторії немає. Ця назва — те, як GitHub іменує архів гілки
(`{репозиторій}-{гілка}`), тож Netlify підключений не до гілки, а до копії,
яку колись розпакували з ZIP в інший репозиторій. Копія не оновлюється й
поступово розходиться: у логу від 07.08.2026 `layout.tsx` був з одного
коміту, а `site.ts` — з попереднього, тому й «Property 'phone2' does not
exist».

Перевірити просто: помилку відтворює лише той репозиторій. Свіжий клон
гілки збирається чисто:

```bash
git clone -b claude/dental-clinic-nataly-site-5l1idu \
  https://github.com/stanwaw052010-coder/demi.git
cd demi && npm ci && npm run build
```

Виправлення — підключити сайт напряму до гілки:

1. Site configuration → Build & deploy → **Link to a different repository**
   → `stanwaw052010-coder/demi`.
2. Branch to deploy: `claude/dental-clinic-nataly-site-5l1idu`.
3. Base directory лишити порожнім — проєкт у корені гілки.
4. Deploys → Trigger deploy → **Clear cache and deploy site**.

## Продуктивність і доступність

Lighthouse (production build): **desktop 100 / 100 / 100 / 100**,
**mobile 93 / 100 / 100 / 100** (performance · accessibility · best practices · SEO).
Мобільний бал стрибає у межах 90–94 від прогону до прогону — це шум
середовища, а не збірки: вага сторінки тримається на 548 КБ.

Фото лікаря на першому екрані має `fetchPriority="low"`: LCP тут — заголовок,
а знімок лежить під ним, тож попереднє завантаження лише забирало б канал.
Перший запуск після заміни фото завжди нижчий — Next генерує оптимізовані
версії на льоту; повторний прогін показує реальні цифри.

- Шрифти self-hosted через `next/font`; сторонніх скриптів немає.
- Секції нижче першого екрана використовують `content-visibility: auto`.
- Зображення віддаються у AVIF/WebP через вбудований оптимізатор Next.
- Інтерактивна карта монтується лише за кліком — жодного стороннього iframe
  на першому завантаженні.
- Контрастність тексту відповідає WCAG AA; декоративні нумерації приховані
  від скрінрідерів.
- Розмітка JSON-LD `Dentist` для локального пошуку.
