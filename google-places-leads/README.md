# Поиск бизнесов без сайта — лидогенерация

CLI-скрипт находит локальные бизнесы (кофейни, стоматологии, автомастерские и т.п.)
в заданном городе/районе, у которых **нет сайта**. Такие бизнесы — готовые лиды
для продажи услуг по созданию сайтов.

В проекте **две независимые версии** — выбирайте под свою задачу:

| Версия | Файл запуска | Источник данных | Ключ / оплата |
|--------|--------------|-----------------|----------------|
| **OSM** (рекомендуется для старта) | `osm_main.py` | OpenStreetMap (Overpass + Nominatim) | **не нужен, бесплатно** |
| **Google** | `main.py` | Google Places API (New) | нужен ключ, платно после лимита |

Обе работают **только через официальные API** — никакого скрапинга
`google.com/maps`, чтобы не нарушать условия использования.

> **Что выбрать?** Начните с **OSM-версии** — она бесплатная, без ключа и
> запускается сразу. Данные OSM полны в крупных городах, но кое-где могут
> отставать от Google. Google-версия точнее по полноте и рейтингам, но платная.

# Версия 1. OpenStreetMap (бесплатно, без ключа)

Использует открытые сервисы OSM: **Nominatim** (геокодинг города → координаты) и
**Overpass API** (выборка заведений по категории в радиусе). «Бизнес без сайта» =
у объекта OSM нет тегов `website` / `contact:website` / `url`.

## Установка

```bash
cd google-places-leads
python -m venv .venv && source .venv/bin/activate   # опционально
pip install -r requirements.txt
```

## Запуск

```bash
# По названию города (геокодинг через Nominatim, затем поиск в радиусе):
python osm_main.py --query "кофейня" --location "Казань" --radius 4000

# По координатам:
python osm_main.py --query "стоматология" --location "55.75,37.61" --radius 3000

# Явно задать тег(и) OSM, если категория не распознаётся автоматически:
python osm_main.py --query "автосервис" --location "Тула" --osm-tag shop=car_repair

# Исключить тех, у кого есть соцсети, и оставить только объекты с названием:
python osm_main.py --query "салон красоты" --location "Самара" \
    --exclude-social --require-name --output samara_beauty.csv

# Только лиды С ТЕЛЕФОНОМ (кому реально можно позвонить):
python osm_main.py --query "автосервис" --location "Тула" --require-phone
```

После запуска телефоны выводятся **прямо в окне** (первые 20 лидов: телефон —
название — адрес), а полный список сохраняется в CSV. Так номер видно сразу, не
открывая файл.

### Аргументы (OSM)

| Аргумент           | По умолчанию      | Описание                                                            |
|--------------------|-------------------|--------------------------------------------------------------------|
| `--query`          | (обязателен)      | Категория: `кофейня`, `стоматология`, `автомастерская` и т.п.       |
| `--location`       | (обязателен)      | Город/адрес (`Казань`) или координаты `lat,lng`.                    |
| `--radius`         | `5000`            | Радиус поиска в метрах (здесь работает всегда).                     |
| `--max-results`    | `0` (без лимита)  | Ограничить число лидов в CSV.                                       |
| `--output`         | `leads_osm.csv`   | Путь к выходному CSV.                                               |
| `--osm-tag`        | —                 | Явно задать тег `key=value` (можно повторять). Отключает автоопределение. |
| `--exclude-social` | выкл.             | Исключить тех, у кого есть ссылка на соцсеть/агрегатор.             |
| `--require-name`   | выкл.             | Оставлять только объекты с заполненным названием.                  |
| `--require-phone`  | выкл.             | Оставлять только те, у кого указан телефон (контактные лиды).      |
| `--overpass-url`   | публичный сервер  | Свой endpoint Overpass (или env `OVERPASS_URL`).                    |
| `--nominatim-url`  | публичный сервер  | Свой endpoint Nominatim (или env `NOMINATIM_URL`).                  |

Автоопределение категорий (`categories.py`) покрывает популярные запросы:
кофейни, рестораны, бары, стоматологии, аптеки, автосервисы, автомойки,
шиномонтаж, парикмахерские, салоны красоты, фитнес, отели, магазины и др.
Если категория не распознана — идёт поиск по названию (`name~query`); для
точности лучше задать `--osm-tag`. Полный список тегов OSM:
<https://wiki.openstreetmap.org/wiki/Map_features>.

### Особенности OSM-версии

- **Бесплатно и без ключа.** Но у публичных серверов есть лимиты: Nominatim —
  не чаще ~1 запроса в секунду (скрипт это соблюдает), Overpass бывает
  перегружен (скрипт делает ретраи; можно указать другой сервер через
  `--overpass-url`).
- **CSV те же столбцы**, что и в Google-версии: `name, address, phone, rating,
  reviews_count, category, map_url, osm_id`. В OSM обычно **нет рейтинга и числа
  отзывов** — эти колонки чаще всего пустые; `map_url` ведёт на openstreetmap.org.
- **Радиус работает всегда** (в отличие от текстового поиска Google).
- Пожалуйста, соблюдайте [Nominatim Usage Policy](https://operations.osmfoundation.org/policies/nominatim/)
  и [Overpass API](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html):
  не делайте тысячи запросов в секунду, для больших объёмов поднимайте свой сервер.

# Версия 2. Google Places API (New)

CLI-скрипт находит те же бизнесы, но через Google Places API (New): «без сайта» =
отсутствует поле `websiteUri`. Точнее по полноте данных и содержит рейтинги, но
**платный** после бесплатного лимита и требует ключ.

Работает **только через официальный Google Places API (New)** — никакого
скрапинга `google.com/maps`.

## Что делает скрипт

1. Ищет места через **Text Search (New)** по текстовому запросу и локации,
   с пагинацией через `nextPageToken` (можно собрать больше 20 результатов).
2. Для каждого места запрашивает **Place Details (New)**: `websiteUri`,
   `nationalPhoneNumber`, `formattedAddress`, `rating`, `userRatingCount`,
   `businessStatus`, категорию и ссылку на Google Maps.
3. Оставляет только места **без сайта**. Опционально (`--include-social`) —
   ещё и те, у кого вместо сайта только соцсеть/агрегатор (Instagram, VK,
   Telegram, 2ГИС, Avito и т.п.).
4. Сохраняет результат в **CSV**: `name, address, phone, rating,
   reviews_count, category, google_maps_url, place_id`.

## Установка

```bash
cd google-places-leads
python -m venv .venv && source .venv/bin/activate   # опционально
pip install -r requirements.txt
```

## Получение API-ключа (Google Cloud Console)

1. Откройте <https://console.cloud.google.com/> и создайте проект (или выберите
   существующий).
2. **Включите биллинг** для проекта: *Billing → Link a billing account*.
   Без биллинга платные API работать не будут (есть бесплатный ежемесячный лимит,
   см. ниже).
3. Включите нужный API: *APIs & Services → Library* → найдите и включите
   **Places API (New)**. Именно «(New)» — старый «Places API» использует другой
   формат запросов и этому скрипту не подойдёт.
4. Создайте ключ: *APIs & Services → Credentials → Create credentials → API key*.
5. (Рекомендуется) Ограничьте ключ: в настройках ключа *API restrictions* →
   выберите **Places API (New)**. Ограничение по IP тоже можно добавить.

Подробнее: <https://developers.google.com/maps/documentation/places/web-service/get-api-key>

## Настройка ключа

Скрипт читает ключ из переменной окружения `GOOGLE_MAPS_API_KEY` через
`python-dotenv`. Ключ **не хардкодится** в коде.

```bash
cp .env.example .env
# затем откройте .env и впишите свой ключ
```

`.env`:

```
GOOGLE_MAPS_API_KEY=AIza...ваш_ключ
```

Как альтернатива — экспортировать переменную окружения напрямую:

```bash
export GOOGLE_MAPS_API_KEY=AIza...ваш_ключ
```

## Запуск

```bash
# По названию города (радиус игнорируется — Google сам определяет область):
python main.py --query "кофейня" --location "Москва" --max-results 60

# По координатам с радиусом в метрах:
python main.py --query "стоматология" --location "55.751244,37.618423" --radius 3000

# Учитывать «только соцсети» как отсутствие сайта и задать имя файла:
python main.py --query "автомастерская" --location "Казань" \
    --include-social --output kazan_auto.csv
```

### Аргументы

| Аргумент           | По умолчанию | Описание                                                                 |
|--------------------|--------------|--------------------------------------------------------------------------|
| `--query`          | (обязателен) | Текстовый запрос: `кофейня`, `стоматология`, `автомастерская`.           |
| `--location`       | (обязателен) | Город/адрес (`Москва`) **или** координаты `lat,lng` (`55.75,37.61`).     |
| `--radius`         | `5000`       | Радиус в метрах. Учитывается **только** при координатах в `--location`.   |
| `--max-results`    | `60`         | Сколько мест максимум обработать (сколько карточек запросить из поиска).  |
| `--output`         | `leads.csv`  | Путь к выходному CSV.                                                     |
| `--language`       | `ru`         | Код языка ответа API.                                                     |
| `--region`         | —            | Код региона для приоритезации (например `RU`).                            |
| `--include-social` | выкл.        | Считать лидами и тех, у кого вместо сайта только соцсеть/агрегатор.       |

> **Примечание про `--radius`.** В Text Search (New) окружность (`circle`)
> задаётся только как «мягкий» ориентир (`locationBias`), поэтому в выдачу могут
> попасть места чуть за пределами радиуса. Радиус учитывается лишь когда
> `--location` задан координатами; для названия города Google определяет область
> сам, и радиус игнорируется (об этом выводится предупреждение).

## Обработка ошибок

- **429 / 5xx** — временные ошибки (rate limit, сбои сервера): автоматический
  повтор с экспоненциальной задержкой (учитывается заголовок `Retry-After`).
- **Понятные сообщения** для типовых проблем: неверный ключ (`API_KEY_INVALID`),
  не включён API или нет доступа (`PERMISSION_DENIED`), превышена квота/нет
  биллинга (`RESOURCE_EXHAUSTED`), неверные параметры (`INVALID_ARGUMENT`).
- Ошибка на детали конкретного места не прерывает работу — место пропускается,
  счётчик ошибок выводится в конце.

## Оценка стоимости

Places API (New) — **платный** после бесплатного лимита. Тарификация — за каждый
запрос, а цена зависит от набора запрошенных полей (SKU-тарифы: *Essentials / Pro
/ Enterprise*). Скрипт делает по одному запросу на страницу поиска (до 20 мест) и
**по одному Place Details на каждое место**.

Грубая прикидка на один запуск с `--max-results N`:

- Text Search: `ceil(N / 20)` запросов.
- Place Details: `N` запросов.

То есть при `--max-results 60` это ~3 запроса поиска + 60 запросов деталей.
Скрипт специально запрашивает в поиске минимум полей (id + название), а «дорогие»
поля (сайт, телефон, рейтинг) берёт точечно в Place Details — так дешевле.

Ориентировочные цены и актуальный бесплатный лимит смотрите на официальной
странице (цены меняются, здесь без конкретных цифр намеренно):
<https://developers.google.com/maps/documentation/places/web-service/usage-and-billing>

> Совет по экономии: следите за `--max-results`, ставьте ограничения на ключ и
> задайте **бюджет и алерты** в Google Cloud Billing, чтобы не уйти за пределы
> бесплатного лимита неожиданно.

## Замечания

- Данные Google Places не всегда полны: у части бизнесов сайт может существовать,
  но не быть указан в Google. `--include-social` помогает не терять лиды, у
  которых «сайт» — это на самом деле страница в соцсети.
- Скрипт не использует скрапинг и не обходит ToS Google — только официальный API.
